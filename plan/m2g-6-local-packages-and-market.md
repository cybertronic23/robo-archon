# M2g.6：本地包管理与市场扩展设计

状态：下一迭代计划，尚未开发。前置：M2g.5 TUI 会话验收。

## 目标

把本体、平台和加载技能的选择保存为可复用会话配置；把现有数据包安装命令接入 TUI，并为未来 Skill/MCP 市场建立可扩展的发现入口。

## 工作拆分

1. 会话配置：保存本体 ID、平台、技能 ID/版本及显示设置；禁止保存 API Key。恢复时重新校验环境和依赖，不自动执行动作。缺失包或版本变化显示明确提示。
2. 本地包管理：浏览来源、版本、契约与依赖；包装现有 ONNX 安装/校验接口。新增卸载/更新流程，阻止修改正在使用的包；保留事务式安装与内容校验。普通数据包不执行任意安装脚本。
3. Runner 扩展：把支持组合与就绪检查注册成适配器接口；用第二种 Runner 的最小验收证明 UI 不依赖 Microduck 硬编码。具体机器人和仿真平台接入独立评估，不能仅列元数据就标为支持。
4. 市场设计：统一展示本地和未来远程的发现结果；Skill 描述运动能力与资源约束，MCP 描述外部工具与连接权限。发现、安装、启用和执行分离，不能把外部工具默认当作机器人控制器。

## 验收边界

- 恢复会话只加载用户确认的能力，缺失依赖阻止进入执行；密钥不进入配置与提交。
- 安装失败不损坏既有包，运行中包无法被卸载；来源和版本可追踪。
- 两种 Runner 共用选择、对话与取消接口，未适配平台显示不可用。
- 远程市场发布、下载服务、MCP 传输和权限实现需后续单独 spec，本迭代不以占位按钮宣称已完成。
